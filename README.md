# Оповещения 74

Telegram-бот оповещений об опасности БПЛА и ракет в Челябинской области. Модуль Go — `chel74alert`.

Следит за публичными RSS-лентами и рассылает подписчикам только объявление и отбой официального режима, а не любые новости про дроны.

## Источники

| Источник | URL | Заметка |
|---|---|---|
| URA.RU | https://ura.news/rss | Общероссийская лента; тревоги по области появляются быстро |
| 74.ru | https://74.ru/text/rss.xml | Местная лента |
| МЧС Челябинской области | https://74.mchs.gov.ru/deyatelnost/press-centr/vse_novosti/rss | Официальная лента; режимы БПЛА туда часто попадают с задержкой или не попадают |

Самый быстрый официальный канал — не RSS, а MAX:

- [РСЧС Челябинская область](https://max.ru/id7453301834_gos)
- МЧС области в MAX: https://max.ru/chelmchs
- Сайт МЧС: https://74.mchs.gov.ru/

Список лент можно заменить переменной `RSS_FEEDS_JSON`.

## На что реагирует бот

Смотрит заголовок и описание записи. Чтобы сообщение ушло в Telegram, должны совпасть регион и официальная формулировка режима.

**Регион** — Челябинская область или город из списка (Челябинск, Магнитогорск, Миасс, Златоуст, Копейск, Озёрск, Снежинск, Троицк, Сатка, Чебаркуль, Кыштым, Аша и др.). Лента МЧС области считается региональной сама по себе.

**Тревога** — рядом стоят угроза и режим, в духе:

- «беспилотная опасность объявлена»
- «объявлен режим „Беспилотная опасность“»
- «ракетная опасность»
- «режим беспилотной опасности введен»

Слова угрозы: БПЛА, БВС, беспилотн…, дрон, шахед, ракетн…, ракета.

**Отбой** — снятие того же режима:

- «отбой»
- «отменили режим беспилотной опасности»
- «режим снят»
- «угроза миновала»

**Не уходит в рассылку**

- криминал и силовики без объявления режима: ФСБ, тайник, задержание, диверсанты
- другие регионы (Пермь, Курган, Свердловск и т.п.)
- сводки «сбили N БПЛА», фестивали дронов, советы «где прятаться» без объявления режима по области

Повторные перепечатки одной волны схлопываются. В рассылку попадают только события за последние `BACKFILL_HOURS` часов.

Словари и правила: `config/config.go` и `sources/filter.go`.

## Запуск

1. Создайте бота в Telegram через [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. Скопируйте `.env.example` в `.env` и вставьте токен.

```powershell
copy .env.example .env
go run .
```

Либо без `.env`:

```powershell
$env:TG_BOT_TOKEN="123:ABC"
go run .
```

В Telegram откройте бота и отправьте `/start`.

Команды: `/start` `/stop` `/status` `/last`.

Если `/start` приходит во время действующей тревоги — оповещение уходит сразу.

В **группу или канал** достаточно добавить бота — `/start` там не нужен. `/stop` в группе может только администратор. Личка по-прежнему через `/start`. Если бота выкинули из чата или пользователь его заблокировал, подписка снимается.

## Тесты

```powershell
go test ./... -short
```

Без `-short` дополнительно проверяется живая лента URA.RU. Если в ней сейчас нет режима по области, тест пропускается, а не падает.

## Docker

Сборка двухстадийная: в образе `golang:1.25-alpine` гоняются `go test ./... -short` и собирается статический бинарник под `TARGETOS`/`TARGETARCH` (по умолчанию linux/amd64; при `docker buildx` — под платформу сборки). В рантайме — Alpine, пользователь `app`, проверка `http://127.0.0.1:8080/healthz`.

```powershell
docker compose up --build -d
docker compose logs -f
```

Перед стартом контейнер проверяет, что читается хотя бы одна RSS-лента и что Telegram `getMe` отвечает. Если проверка падает — бот не поднимается, `restart: unless-stopped` повторит попытку. Если процесс завис — `HEALTHCHECK` пометит контейнер unhealthy.

Локальный прокси `127.0.0.1` из контейнера недоступен. Замените на `host.docker.internal`, например `TG_PROXY=http://host.docker.internal:10809`.

## Переменные

| Имя | Смысл | По умолчанию |
|---|---|---|
| `TG_BOT_TOKEN` | токен бота | обязателен |
| `TG_PROXY` | HTTP или SOCKS5 прокси до Telegram | пусто |
| `TG_PROXY_USER` | логин прокси | пусто |
| `TG_PROXY_PASSWORD` | пароль прокси | пусто |
| `POLL_INTERVAL` | как часто опрашивать RSS | `60s` |
| `BACKFILL_HOURS` | окно «догона» при первом запуске | `6` |
| `EVENT_COOLDOWN` | не слать повтор той же волны (опасность/отбой) | `90m` |
| `DATA_DIR` | где хранить подписчиков и уже виденные GUID | `data` |
| `SKIP_PREFLIGHT` | `1` — не проверять RSS/getMe при старте | `0` |
| `HEALTH_ADDR` | адрес `/healthz`; пусто — не слушать. В Docker: `127.0.0.1:8080` | пусто |
| `RSS_FEEDS_JSON` | заменить список лент JSON-массивом `{name,url,region_implicit}` | вшитые URA.RU / 74.ru / МЧС |

Подписки сохраняются в `data/state.json`. Одновременно может работать только один процесс на каталог данных.

## Если `api.telegram.org` даёт EOF

В ряде сетей Telegram режут на TLS. Бот тогда не стартует, токен тут ни при чём.

1. Поднимите VPN или локальный прокси (Clash, v2rayN, Outline и т.п.).
2. В `.env` укажите его, например:

```
TG_PROXY=http://vpn.example.com:42533
TG_PROXY_USER=login
TG_PROXY_PASSWORD=secret
```

Можно и в одной строке: `TG_PROXY=http://login:secret@vpn.example.com:42533`. Если в пароле есть `@`, `:`, `#` или `/`, лучше отдельные `TG_PROXY_USER` / `TG_PROXY_PASSWORD`.

3. Если токен уже светился в логе — в @BotFather выполните `/revoke` и вставьте новый в `.env`.
